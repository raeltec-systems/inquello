## Binding direction and experience intent

PRD §§0–3 and 6: internal product/design audience; a Codex-derived workbench preserving broad agent execution and conversational continuity for internal/external audit, advisory and IT/IS audit. First validation with one organisation's audit team is not a permanent market boundary. Existing work comes first: users bring a question, files, a method or an optional Assignment, then steer, inspect, revise and deliver. Ordinary review must not require code expertise; real code, query, shell and security capabilities remain available to specialists.

**V1:** the complete researched capability target and required audit adaptations, with existing authoritative external audit records and supported working files. Includes automation, continuous assurance, approved unattended work and all smaller features. No narrower MVP or initial shipping increment has been selected. Any deferral remains explicit unmet scope.

**V2:** FR-38, FR-40 and FR-42, plus associated native-record responsibilities: authoritative identities/relationships, attributed decisions, reviewed versions, amendment, retention/hold/deletion, recovery/export and organisation/workspace mode choice/migration. These do not gate V1. Operational ledgers/HR/transactions remain separate in either phase. Additional portfolio, staffing, assurance-mapping, quality-programme and workflow-builder suites remain unprioritised candidates.

**Interaction intent:** conversation directs visible work, the practitioner retains control, and the same saved artifacts remain usable in Excel/Word/PowerPoint and other supported editors. Methods are taught/refined using examples, instructions, skills, tools, agents, configuration and memory. No universal method, control object, review hierarchy or mandatory engagement setup. No compulsory proprietary conversion or promise of universal live application access. Default execution is scoped and user-started; broader unattended mandates are explicit. Processing policy and provider capability limits remain visible without conflating execution with inference.

**Responsibilities:** practitioners prepare; authorised humans review/challenge/reject/request correction/approve; leads scope and coordinate; specialists inspect technical analysis; administrators/method owners govern resources and guidance. Responsibilities can overlap under policy. Agent roles never create professional approval or independence. Guest participation remains open.

## Cross-cutting interaction distinctions

- **Separate authorities:** instruction source, acting account, permission to run, result verification, human review, professional approval, delivery and authoritative record acceptance. A single “done” badge cannot represent all.
- **Separate state axes:** running/blocked/interrupted and produced/checks/review/delivery are semantic distinctions, not a mandated global state machine. Advisory work can use fewer applicable steps than a signed workpaper.
- **Separate material:** Source versus Method versus Artifact versus authoritative record; saved state versus live application state; personal preferences versus approved reusable knowledge versus client evidence; memory contribution versus use; activity capture versus recall.
- **Preserve work across boundaries:** external editor, parallel agent, branch, different access surface or execution location, compaction and interruption. Explain inaccessible/stale/missing/transferred-with-loss context rather than simulate continuity.
- **Long-tail scope stays visible:** physical controls, CLI/session commands, structured streaming, side chats/branches, app snapshots, browser annotations, generated/hosted outputs, migration, voice, companions, memory/activity controls and actual security work. Any future deferral is explicit.

- **A01–A18** retain ad hoc work, practice breadth, all fixtures, agent disagreement, resumption/revocation, external writeback, phase-specific authority, event states, sharing, route limits, smaller features, presentation themes/charts/notes and total-effort evaluation. UX should expose the evidence needed to measure these, not optimise for generated-output counts.
