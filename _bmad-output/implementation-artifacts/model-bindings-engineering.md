## Exact persistence and command design

Reuse `processing_route_candidates` keyed by `(principal_id, route_id, revision)` as immutable binding configuration. Expose a bounded opaque binding ID that resolves to that owned tuple; never accept another principal from renderer input. Preserve `task_processing_routes` and its existing exact foreign key and selection history. Never map historical Tasks to `MAX(revision)`.

`engine/codex-rs/inquello-adapters/migrations/0016_model_bindings.sql` adds one table keyed/FK to that tuple, with active/revoked/legacy-superseded state and independent CAS revision. Previously current configurations migrate active as configuration records only, without credential/qualification grants; superseded records migrate unavailable. Deliberate legacy revalidation targets the SAME exact supported configuration, not a replacement model. Revoked/unsupported or mismatched-account configurations stay unavailable. No preference or provider-connections table.

Reuse `processing_route_receipts` for binding operations and maintain global operation-ID collision detection across all commands. Its current CHECK accepts only `configure_route` and `set_task_route`. Widen this constraint transactionally in the new migration, preserving every existing column/value/index and old receipt interpretation; do not edit migration 0006. Explicit binding revoke/revalidation commands have distinct receipt kinds, canonical payloads, exact scope and state CAS. Verify byte preservation and foreign-key integrity before/after migration. A repeated operation returns its recorded outcome without creating a second configuration; conflicting payload/owner/command under the same ID is refused. Resolve/create by opaque catalog choice/version appends or returns an owned exact binding; it never reactivates an unavailable legacy row silently.

`engine/codex-rs/inquello-domain/src/routes/model.rs`, `ports.rs`, `commands.rs`: add exact state reads/mutations; replace `task_route()` staleness/latest checks and `set_task_route()` latest restriction. Keep creator authorization before receipt replay. `engine/codex-rs/inquello-adapters/src/routes.rs`: reuse `load_candidate_route_record`; atomically validate exact active state in `commit_task_route`, with state/selection CAS. `src/tasks.rs::commit_task_start` independently checks latest candidate today; replace that guard too.
