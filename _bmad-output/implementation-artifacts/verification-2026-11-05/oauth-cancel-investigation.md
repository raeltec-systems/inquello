## Established facts

- Approved Story 1.21 lines 69,99,108 authorizes genuine runtime MCP cancellation, atomic cancellation versus credential persistence, exact attempt targeting, and isolated regression fixtures. No new product decision is needed for a lifecycle repair preserving these rules.
- `rmcp-client/src/perform_oauth_login.rs:694-696,764-775` gives both flow guard and blocking callback consumer an Arc to tiny_http Server. The consumer exits on its first recognized callback (`290-345`). The guard lives through token exchange (`833-869`) or is dropped when the cancellation select drops `self.complete` (`880-884`). Its Drop only calls `server.unblock` (`75-83`), which wakes the request consumer, not transport workers.
- `callback_closed` (`789-790`) observes the consumer's drop guard (`297-299`). It does NOT establish closure of the TCP listening socket or accepted connections. On successful callback it can signal while the flow still owns its Server Arc and waits for token exchange.
- Cached tiny_http 0.12.0 source: lib.rs:421-436 sets an accept-thread flag and self-connects during Server::drop; it does not join the accept thread. lib.rs:321-338 gives each independent client worker a messages-queue Arc and iterates requests without consulting that flag. client.rs:177-258 keeps HTTP/1.1 clients alive unless the REQUEST requests close. After the OAuth consumer exits, these workers can enqueue another request that nobody consumes. Queue/request/client ownership can keep accepted sockets alive independently of Server ownership.
- Concrete explanation for the earlier ineffective mitigation: tiny_http response.rs:16-22 and 257-263 explicitly discard supplied Connection headers. Adding `Connection: close` to a Response cannot close these connections.
- The deferred-work Linux report establishes a timed-out retry even with a reportedly fresh connection, but source inspection alone does not prove that an entirely new TCP connection survives the final accept-thread shutdown. Separate an accepted/reused connection from an actual still-listening socket before claiming that precise root cause. No socket-level reproduction was run here.

## Authority and arbitration to preserve

`oauth_login_cancellation.rs:41-47` marks Cancelled under the shared state mutex and wakes cancellation. `65-83` holds the same mutex throughout `write.await`; an already-started write wins and cancel reports Completed/Failed, never false cancellation. `perform_oauth_login.rs:880-892` selects cancellation before persistence, not around persistence. Do not abort the persistence future, weaken the mutex, or remove the late-write check. `mcp_processor.rs:98-106,149-186,500-510` selects and registers exact server/login ID and the same cancellation control. No evidence here calls for changing this authority.

## Minimal repair boundary

Repair the callback-server owner in perform_oauth_login.rs; do not change the public protocol, provider validation, callback-path/state/issuer rules, credential policy, or cancellation arbitration. A consumer-unblock or extra sleep is insufficient; ownership must terminate BOTH listening and accepted connections, and completion must observe that termination.

A small robust implementation option is replacing only this tiny_http callback transport with the already-declared axum/tokio dependencies (rmcp-client/Cargo.toml). Bind a Tokio listener, preserve the exact SocketAddr-derived redirect helper behavior, retain the existing parser, use a single-use sender for the first terminal callback, reject subsequent callbacks, send genuine Connection: close responses, and use an owned shutdown token plus awaited server termination. Guard Drop requests shutdown; callback_closed is signalled only after the transport future/connection shutdown finishes. Make spawn wait for actual closure before publishing its completion result. Check preaccepted idle/partial-header sockets explicitly: simply aborting axum::serve is not proof that its spawned connection tasks died, and graceful shutdown must not wait indefinitely. If that approach cannot satisfy bounded teardown, explicitly own/close the connection tasks rather than claim completion early.

Before choosing code, reproduce the existing regression and distinguish listener from keep-alive survival. A narrower proven repair is preferable if it closes every owned socket without an unrelated transport rewrite. Do not patch cached registry files or add dependencies. A new dependency or broader auth change requires escalation, not an automatic install.
