# Codex and Claude Code capability crosswalk

**Research cut-off:** October 22, 2026  
**Scope:** the 78 capability and product-lens rows in [CODEX_CAPABILITY_CATALOG.md](CODEX_CAPABILITY_CATALOG.md) (75 capability rows plus three product-lens rows), mapped against Anthropic's current official Claude Code documentation and official public repository. This is a documented-capability comparison, not a hands-on benchmark, product ranking, design decision, or claim about private internals.

## How to read the status

- **Documented analogue** — Claude Code documentation describes the same broad capability family.
- **Partial / different** — a related capability exists, but the product surface, control model, or output differs materially.
- **No direct match found** — no direct counterpart was located in the official docs reviewed. This does not prove that no such capability exists.
- **Not a Claude Code feature** — the Codex row is a product hypothesis for the auditor tool, rather than a capability to compare.

“Documented analogue” does not mean equivalent implementation or quality. “Potentially useful difference” identifies an approach to investigate; it does not say that one product is superior for every use.

## Patterns worth investigating, not product rankings

These differences are especially useful to study because they offer distinct operating patterns. They are not conclusions that one tool is better overall.

1. **Coordinated agent teams:** Claude documents peer-to-peer teammate messaging and a shared task list; agent teams are experimental. Compare this with Codex's parent-coordinated subagents, separate chats, and concurrent work. It may offer a different model for parallel research and cross-checking, with different coordination and review costs. [C7, C8]
2. **Live interactive outputs:** Claude Artifacts can be live pages that update with a session, accept comments, pull connector data, and have audience controls. Compare this with Codex file previews and Sites' separate publishing/version lifecycle. [C18]
3. **Extension packaging:** Claude plugins can package skills, agents, hooks, MCP servers, and UI mods in one installable unit. Compare that with Codex's skills/plugins/apps split, its authorization model, and which pieces are project-local versus account/workspace-wide. [C4, C15, C16]
4. **Permission model:** Claude documents fine-grained allow/ask/deny rules, managed policy, sandboxing, and an auto-mode classifier. Compare how effective policy is calculated and presented against Codex's filesystem/network sandbox, approval modes, command rules, and Agent Security layers. [C5, C12, C29, C31]
5. **Automated review:** Claude documents local and GitHub review plus multi-agent Ultrareview that verifies findings. Compare review coverage, supporting evidence, false-positive handling, and the human's final action with Codex Code Review and separate Codex Security review flows. [C17]
6. **Public evidence boundary:** Codex's public repo includes core runtime/app-server areas; Claude's official public repo is an extension/examples surface under an all-rights-reserved license. Compare the published integration contracts and documented behavior; source-level parity is not available from these two repositories. [C19, C33]

## Documentation-index attribution boundaries

The current Codex docs index mixes Codex-specific pages with shared ChatGPT, Work, Dots, API, and administrator documentation. It is a discovery index, not proof that every indexed capability belongs to every Codex surface. This pass added shared capabilities explicitly documented for Codex and separated them from adjacent product families:

- **Codex Micro:** a limited-run physical peripheral that maps keys to chats, status, approvals, skills, voice, and common desktop actions. It is covered in the Codex product-surface inventory; hardware and OS constraints remain relevant. [Codex Micro documentation](https://learn.chatgpt.com/docs/features/codex-micro)
- **Shared ChatGPT capabilities explicitly available in Codex:** image generation, browser annotations, Record & Replay, and optional companion pets have dedicated capability entries with client/platform limits where available.
- **WebMCP site tools:** the guide says Work/Codex may interact with forms through regular browser capabilities without those interactions being WebMCP tool calls. Keep WebMCP separate until Codex-specific tool-call support is documented. [Site tools](https://learn.chatgpt.com/docs/webmcp)
- **Other product families:** Dots and ChatGPT Space are separately documented agent/workspace products. Keep their capabilities outside the Codex catalog unless documentation establishes a Codex surface or shared runtime behavior; they may be useful future comparators to Work.
- **Security, enterprise, and integrations:** the index includes dedicated Codex Security surfaces, access/service-account and gateway controls, usage/governance surfaces, GitLab support, and third-party entry points. The catalog groups these by capability and points to underlying product-specific workflows in its source register.

The current Codex catalog is a broad public-evidence capability map, not a verified exhaustive implementation inventory. This crosswalk maps its current entries; “not found” means not found in the reviewed official Claude Code documentation, not confirmed product absence.
