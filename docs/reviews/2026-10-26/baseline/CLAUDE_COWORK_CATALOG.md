# Claude Cowork capability and workflow catalog

**Research cut-off:** October 22, 2026  
**Purpose:** document Claude Cowork as a knowledge-work product and compare its workflow layer with Codex and ChatGPT Work. This is scouting, not a product or architecture recommendation.  
**Evidence:** Anthropic product/help/security documentation and official announcements. No live Cowork account was operated and no private product source was inspected.

## Product boundary and current state

Anthropic introduced Cowork as a desktop experience for delegating multi-step work across local files and connected services. Current help material describes it on paid Claude plans, with desktop availability across Pro, Max, Team, and Enterprise and web/mobile availability varying by plan and rollout. Anthropic is gradually unifying Chat and Cowork into one Claude experience: in that rollout the user describes the task in a conversation and Claude chooses whether to answer or run a task. Team and Enterprise availability and some cloud surfaces remain beta or admin-controlled. Record the account, plan, client, and rollout state before treating a flow as universal. [Launch context](https://www.anthropic.com/news/introducing-anthropic-labs), [surface and rollout matrix](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)

Anthropic describes Cowork as a visual way to hand off complex work using Claude's agentic capabilities. That describes the product relationship; it does not establish that Cowork and Claude Code share the same implementation, process, or runtime. The official [`anthropics/claude-code`](https://github.com/anthropics/claude-code) repository publishes extensions, examples, scripts, and related materials, but its license reserves rights and it is not the source for the Claude Code or Cowork product implementation. The public [`openai/codex`](https://github.com/openai/codex) source likewise documents Codex, not ChatGPT Work. Keep these evidence streams separate.

## Capability inventory

| Area | Documented behavior | Evidence boundary and research lens |
| --- | --- | --- |
| **Task entry and handoff** | A user starts from Claude's common home, describes a multi-step task, reviews Claude's proposed approach where offered, answers follow-up questions, and lets it work. Users can steer a running task and review the result. The UI is being unified with ordinary chat, so a permanent “Cowork mode” selector is not guaranteed. | This is a task-oriented layer over conversation. Compare task framing, plan visibility, clarification points, steering, completion, and review with [ChatGPT Work](FEATURE_CATALOG.md) and Codex threads; do not assume a shared harness from similar UX. [Getting started](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork) |
| **Surfaces and continuity** | Cowork can be accessed from desktop, web, and mobile, with availability differences by plan. Users can start, steer, review, and resume sessions across surfaces. Local folders, local MCP servers, browser access, and computer use still depend on the desktop app being available. | Separate where the agent runs from which device controls or reviews it. An off-desktop session may continue while losing access to local resources if the desktop app goes offline. [Surface matrix](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile) |
| **Projects and working context** | Projects group related tasks with instructions, context, files or links, scheduled tasks, and project memory. They can be created from scratch, from an existing Claude project, or around a selected local folder. Team/Enterprise users can share projects with view/edit access. In the current rollout, cloud projects follow the Claude account across devices; files in a local folder remain on the device. Project memory can also use account memory unless the user disables it for that project. | Projects resemble durable workspaces but do not constitute the authoritative business record. Check memory scope, sharing, local/cloud conversion, account-memory interaction, and whether project instructions apply consistently across Chat, Cowork, and Code. [Projects](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork) |
| **Cloud and local execution** | Current Cowork sessions run in an isolated, temporary cloud sandbox by default on Pro and Max. Cloud Cowork is in beta on web/mobile for Team and on Enterprise when enabled. Older desktop sessions and scheduled tasks started locally before October 6, 2026 may remain local. When cloud sessions need local files or browser access, requests are brokered through the user's desktop app; connected-folder permissions are checked, and the desktop must be online. | This is a time-sensitive architectural split. Anthropic's May 2026 engineering article describes an earlier local VM design; current Help Center architecture distinguishes cloud-by-default sessions from remaining local deployments. Do not blend these modes into one fixed architecture. Cloud processing includes files fetched from the device. [Current architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview), [engineering account of containment](https://www.anthropic.com/research/how-we-contain-claude) |
| **Files and local folders** | Cowork can read and write files in folders the user connects. It can organize files and produce documents, spreadsheets, presentations, and other deliverables. In cloud sessions a needed local file is fetched through the desktop app and processed on Anthropic's servers; the original folder remains on the device. The Cowork folder and downloaded task data can be exported or continued in Claude Code using documented handoff steps. | Folder scoping, file-level copies, execution location, persistence, and export need separate treatment. File access is not proof that the output was saved into a practitioner-owned system of record. [Architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview), [surface details and task export](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile) |
| **Connectors and external services** | Remote connectors let Claude search or act in cloud services. Connector authorization normally follows the user's permissions in the source service; shared credentials can expose whatever the shared account can access. In Cowork, connector calls reach external services through Anthropic's cloud. Local desktop extensions can connect to local files, databases, or processes, but local MCP servers work through desktop rather than web/mobile. | Distinguish user identity, shared credentials, remote connectors, local extensions, and the account represented to each source. A connector's reach is not limited by a local command sandbox. [Connectors](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities), [connector versus desktop extension](https://support.claude.com/en/articles/11725091-when-to-use-desktop-and-web-connectors) |
| **Skills, plugins, and customization** | Skills hold reusable instructions and domain knowledge. Plugins can bundle skills, connectors, and subagents into an installable package; depending on the plugin and surface, they may also include hooks and local or remote MCP servers. Organization owners can distribute curated plugin marketplaces. Users can customize an installed plugin's skills and connectors. | This packaging model has a close conceptual analogue to Codex skills/plugins/MCP, but extension scope and execution differ by surface. Review executable local MCPs and plugin sources separately from prompt-only skills. [Plugins](https://support.claude.com/en/articles/13837440-use-plugins-in-claude), [connector extension types](https://support.claude.com/en/articles/11725091-when-to-use-desktop-and-web-connectors) |
| **Agents and parallel work** | Cowork is described as coordinating multi-step work and parallel workstreams. Plugins may bundle subagents for specific subtasks. Anthropic's financial-services templates package skills, governed connectors, and subagents for tasks such as methodology checks, KYC screening, pitchbook work, and month-end close. | The product pages describe outcomes and packaged patterns, not the complete coordination protocol. Record what is known about agent context, delegation criteria, permissions, isolation, result synthesis, and user visibility; leave undocumented behavior unknown. The finance examples are workflow references, not an assurance methodology. [Financial-services agent templates](https://www.anthropic.com/news/finance-agents) |
| **Permission mode and human oversight** | In the unified Claude experience, Auto mode is the default on Pro, Max, and Team and lets tasks proceed with automated safety checks; Manual mode is the Enterprise default and asks before actions. The setting applies to the conversation, and users can stop or redirect work. Computer use has a separate, weaker prompt-check boundary than ordinary tools. | An automatic safety check is not the same as a deterministic policy rule, audit approval, or independent workpaper review. Compare the action classes that prompt, the automated checks, their failure behavior, and the evidence left for reviewers. [Unified Claude experience](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude), [safe-use guidance](https://support.claude.com/en/articles/13364135-use-claude-cowork-safely) |
| **Browser and computer use** | Cowork can use a built-in browser and, in supported setups, Claude in Chrome. Computer use can click, type, and navigate desktop apps; browser/computer access from web or mobile is mediated by the desktop app. Anthropic warns that computer use has different safety properties from other Cowork tools and that its actions do not pass through the same permission checks. | Separate page research, signed-in browser access, app automation, and computer-use permissions. GUI visibility does not establish what the app exposes outside the visible screen, nor does it make a consequential action safe. [Safety guidance](https://support.claude.com/en/articles/13364135-use-claude-cowork-safely), [surface matrix](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile) |
| **Outputs and artifacts** | Cowork creates files and reviewable outputs. Artifacts provide a separate editable/shareable surface for documents, slides, designs, dashboards, and interactive tools. Users can edit by prompting or directly, export supported formats, and share according to artifact-specific access rules. Newer artifacts work across more surfaces than older Cowork live artifacts; some templates and app/data features are beta or plan-controlled. | Compare an artifact/document with a generated file, an interactive tool, and an authoritative workpaper. Sharing a view or artifact does not transfer source-system ownership or prove review/sign-off. [Artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them), [Cowork live-artifact transition](https://support.claude.com/en/articles/14729249-use-live-artifacts-in-claude-cowork) |
| **Scheduled work** | A scheduled task stores instructions and a recurrence or on-demand trigger, then runs as its own Cowork session. It can use configured connectors, skills, and plugins. Users can review upcoming and previous runs, edit, pause, resume, delete, or run on demand. Cloud schedules can run while the device is asleep; tasks requiring local apps/files have local-execution constraints, and legacy local schedules may persist. | Similar to Work automations and Codex scheduled tasks at a high level, with different execution, identity, and local-resource behavior. Compare trigger scope, unattended permissions, run history, failure notices, output location, and who is expected to review each run. [Scheduled tasks](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork) |
| **Remote steering / Dispatch** | Dispatch historically let a user send work from a phone to a desktop-backed task using its files, connectors, plugins, and apps. Current help material says Dispatch is not available to new users during the transition to the unified Claude experience, though existing users may continue using it. | Treat this as a distinct, rollout-sensitive remote-control path, not a generally available guarantee. Any mobile request that can trigger desktop file, connector, browser, or app actions needs the full chain of identity and authorization recorded. [Dispatch](https://support.claude.com/en/articles/13947068-assign-tasks-from-anywhere-in-claude-cowork) |
| **Security and administration** | Cloud sessions use per-session temporary sandboxes, deny private/internal network routes by default, apply organization egress policies through an external proxy, and use short-lived session credentials. Connector tokens are handled server-side. Enterprise admins can control Cowork availability, cloud sessions, network access, and device-level local MCP/extension settings. | Isolation constrains execution reach; it does not determine whether a connected source contains trusted content or whether a granted connector can take high-impact actions. Study read/write tools, prompt injection, egress as a capability grant, admin policy scope, and what review evidence is preserved. [Architecture](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview), [safe-use guidance](https://support.claude.com/en/articles/13364135-use-claude-cowork-safely) |
| **Retention and portability** | Cloud sessions and files are associated with the Claude account. Users can export Cowork data or download task data; downloaded tasks can be continued in Claude Code. Local-session data and files remain subject to local storage and account-specific behavior. | The documentation supports task-data portability, not an immutable, complete activity log or system-of-record role. Confirm retention, deletion, export coverage, and the status of connector and tool-call history for each plan before drawing stronger conclusions. [Surface and export details](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile) |

## Cross-product comparison lens

This is a comparison of documented product behavior, not a ranking. The Codex behavior is catalogued in [CODEX_CAPABILITY_CATALOG.md](CODEX_CAPABILITY_CATALOG.md), and ChatGPT Work in [FEATURE_CATALOG.md](FEATURE_CATALOG.md). Claude Code's developer-oriented comparison remains in [CODEX_CLAUDE_CODE_CROSSWALK.md](CODEX_CLAUDE_CODE_CROSSWALK.md).

| Question | Codex | ChatGPT Work | Claude Cowork | Auditor-product study question |
| --- | --- | --- | --- | --- |
| What is the organizing unit? | Projects, chats/threads, and execution environments; strong repository/workspace framing. | Outcome-oriented tasks and reviewable outputs across files, connected apps, and schedules. | Tasks/sessions grouped by projects with instructions, context, memory, files, and schedules. | Which unit should hold reusable engagement context while allowing the practitioner to move between discrete outputs? |
| Where does work execute? | Local, worktree, remote host, or Codex Cloud, with distinct policy and available resources. | Local or cloud Work paths, with product-specific tools and controls. | Cloud by default for new Pro/Max work; local-resource access may be mediated by desktop, with older local sessions retained. | How should an auditor see the execution location, source-data path, and device dependency at each step? |
| How is the agent customized? | Instructions, memory, skills, plugins, MCP, and hooks, with different scopes and trust boundaries. | Work skills/plugins, connected services, task context, and product workflows. | Skills/plugins package domain workflow, connectors, and subagents; marketplace distribution supports organizations. | Which customization should be practitioner-configurable, team-approved, or technically enforced? |
| How are agents coordinated? | Subagents and concurrent tasks have documented runtime/client behaviors; parent agent usually synthesizes delegated results. | Work offers task delegation and available subagent/parallel workflows by surface. | Multi-step workstreams and plugin subagents are documented, but the full coordination contract is not public. | What evidence should show task ownership, delegation, independent analysis, and review of synthesized results? |
| What is the output model? | Conversation, files/diffs, previews, Sites, and code-review surfaces. | Generated and reviewable files/visual outputs designed around user outcomes. | Files plus editable/shareable artifacts and export templates. | Which outputs must be easy to take into the practitioner's existing evidence repository, GRC platform, spreadsheets, or reporting tools? |
| What is the trust model? | Sandbox/approval separation, app/MCP identity, managed policy, and environment-specific controls. | Local/cloud execution and connector/app controls are product-specific. | Isolated cloud sessions, egress policy, source permissions, desktop-mediated local access, and admin controls. | How should source authority, read versus write capability, data residency, approval, and activity evidence be made explicit without turning the tool into a system of record? |

## Open evidence questions

- Directly observe one authorized Cowork workflow to verify how approach review, progress updates, questions, permissions, and output review appear in the current unified experience.
- Establish which behaviors are common to Claude Chat, Cowork, Claude Code, plugins, and Anthropic Platform, rather than inferring shared runtime from user-facing similarities.
- Trace current artifact export, sharing, comments, connector data refresh, and user-level access in a live session.
- Verify plan- and organization-specific controls for projects, memory, local files, computer use, plugin marketplaces, retention, and activity records.
- Continue the Codex catalog reconciliation and compare Claude Code on each capability family. The current 78-entry crosswalk concerns Claude Code only; it does not imply Cowork parity.
- Compare other agent products after this pass if the evidence shows useful differences. No design, architecture, or implementation choices are made in this scouting document.
