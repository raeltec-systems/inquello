# How Codex learns a team's way of working

**Checked:** October 26, 2026. **Question:** Q8 — start with Codex's existing mechanisms, then identify the auditor equivalent. **Status:** documentation and public-source research; no product implementation, skill installation, configuration change or live workflow trial.

Codex lets users express a methodology through task context, durable instructions, reusable skills, tools and specialist agents. Memory helps recall prior work. Configuration and execution controls govern how the agent may operate. These layers can be combined without requiring the user to build a formal workflow application. This is the starting point for the audit adaptation, not a decision to impose a new methodology engine. [Customization](https://learn.chatgpt.com/docs/customization/overview)

## What a user actually does

1. **Describe an outcome and supply examples.** Give the task, relevant files, an acceptable output and how to check it. For an auditor, this could be an existing workpaper, the team's procedure and the supplied population. The product should be useful before someone creates reusable configuration. [Best practices](https://learn.chatgpt.com/docs/learn/best-practices)
2. **Make repeated guidance persistent.** Put working conventions and recurring review feedback in `AGENTS.md`. Codex discovers applicable guidance along the project path. An audit analogue is a team's work instructions, supplemented by assignment-specific context. A folder hierarchy alone must not be treated as a confidentiality boundary. [Project instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
3. **Turn a repeatable procedure into a skill.** A skill packages instructions, references, templates and optional executable helpers. Users can describe one to the skill creator or author its files. Skills can be invoked explicitly or selected from their descriptions; full instructions load when needed. For auditors, this can express an existing reconciliation, walkthrough or access-review procedure. [Build skills](https://learn.chatgpt.com/docs/build-skills)
4. **Connect the required capabilities.** A skill explains the workflow around tools; MCP supplies access to external information and actions. The audit procedure might work entirely on saved files, or use a connector where a remote operation is needed. Possessing a procedure does not grant access to a source system. [Skills and tools](https://developers.openai.com/plugins/concepts/skills)
5. **Improve the method from reviewed results.** Codex guidance describes incorporating repeated corrections into persistent instructions. Our proposed audit equivalent is to review a successful procedure, correct it and preserve the reusable parts, while keeping case-specific evidence separate. Updating a general method should not silently rewrite a completed assignment. [Customization](https://learn.chatgpt.com/docs/customization/overview)

These are instruction/context mechanisms. The examined sources do not require a model-training project to teach this way of working. A natural-language instruction can guide behavior; it does not prove that a professional requirement was satisfied.

## What this changes about Q8

The evidence supports starting with the same layered experience: **bring your work, explain your method, reuse it as guidance or a skill, and improve it through review**. A future auditor interface could make those mechanisms accessible without requiring users to edit Markdown/TOML directly. That interface is a later design decision; the mechanisms already give us a concrete research baseline.

The previous menu made instructions/templates, versioned packs and a workflow builder sound like competing starting points. Codex already combines instructions, files, skills and distribution. We should test that combination before deciding whether an additional builder is necessary. Calling a bundle a “method pack” adds no capability by itself.

For the selected **one-team** validation setting, investigate these first-layer adaptations:

- **Visible method provenance:** identify applicable guidance, procedure/package versions and assignment-specific parameters used for a result. Keep them alongside the work product, subject to retention policy.
- **Separation of reusable method and case evidence:** a client's records or last year's conclusions must not silently become general team instructions or shared memory.
- **Explicit change handling:** identify outputs affected by a changed procedure, template or source. Recompute or route for review as appropriate; do not silently preserve an obsolete approval.
- **Checkable completion:** separate generating an output, validating it, human review and formal sign-off. Prefer deterministic checks for amounts, populations and required relationships when appropriate.
- **Scope-aware authority:** the organisation/workspace sets the audit-record mode (Q3 A); a task or skill must not silently select another authority model. Remote record updates follow reviewable writeback (Q4 B).

These are proposed adaptations for the full functional mirror, not accepted detailed architecture or automatically deferred V2 additions. Exact review roles, method publishing rights, overrides and retention requirements still need real team evidence.

## Important distinctions found

**Instructions and enforcement:** prose tells an agent what to do; the permissions, tools and record system determine what it can do. Managed hook documentation warns that some callback failures/timeouts do not block tools. A workflow must demonstrate its actual failure behavior before a control claim is made. [Managed configuration](https://learn.chatgpt.com/docs/enterprise/managed-configuration)

**Method and memory:** local memory is generated context with controls and eligibility conditions, not an automatically maintained shared team methodology. Separate clients and hosts can have different memory stores. Our team-sharing and cross-engagement behavior remains a product question. [Memories](https://learn.chatgpt.com/docs/customization/memories)

**Definition and distribution:** a local procedure can be authored as a skill; packaging and distributing it is a separate concern. The public documentation describes those roles, but does not establish our future release, approval or compatibility process. [Plugins](https://developers.openai.com/plugins/build/plugins)

**A role label and an access boundary:** calling an agent a reviewer does not establish independence or read-only access. Subagent permissions follow the parent under the documented mechanism. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
