| ID / priority | Assumption or blindspot | Assessment and consequence | Related choices |
| --- | --- | --- | --- |
| F01 / Before architecture | Everything seen in Codex can be carried into our product through its public repository or a subscription login. | **Unproven and partly contradicted by service boundaries.** The repository, desktop UI, model service, hosted tools, connector entitlements, and authentication routes are distinct. The catalog now records the missing authentication boundary. A capability must have a feasible, eligible supply route before it is treated as reusable. | Q1, Q11, Q15; U1 |
| F02 / Before requirements | Mapping every Codex row gives us an exhaustive audit-product feature list. | **False inference from a correct row count.** We need a reverse inventory from each competitor's own objects and from practitioners' work. Missing Diligent equivalents for peripherals are low-priority reference gaps; they are not automatically unanswered product requirements. | Q2, Q12, Q15; U2, U8 |
| F03 / Before requirements | The two modes are simply a storage setting. | **Materially incomplete.** They change record authority, permissions, review status, conflicts, writeback, migration, and deletion. An engagement needs a clear authoritative owner for each record class. External mode still holds working copies/history; built-in audit records need not replace ERP, ledger, HR, or ticketing transaction sources. Mode changes require a deliberate handoff, not an unexplained toggle. | Q3, Q4, Q9; U3, U4 |
| F04 / Before requirements | End-to-end means every task follows a formal engagement lifecycle. | **Too narrow for the stated workbench ambition.** Research, advice, investigations, ad hoc analysis, and single outputs may have no engagement. At the other end, annual/portfolio planning, staffing, budgets, and quality programmes broaden the product beyond engagement execution. The user needs to choose the desired perimeter. | Q2 |
| F05 / Before requirements | Conversation alone is the work environment. | **Direction clarified by the user.** Retain Codex's conversational workspace with inspectable work and support continued work on the same saved artifacts in existing tools. The intent is established; detailed review/editing behavior, fidelity, change detection, and live-app interaction remain unverified. | Q5, Q13 resolved in direction; U5, U6 |
| F06 / Before requirements | Subagents and a reviewer agent cover collaboration and independent review. | **Category mismatch.** Human preparers, managers, partners/CAE equivalents, evidence providers, administrators, and clients have different access and authority. Coauthoring, conflicts, temporary access, reassignment, departure, delegation, and professional sign-off remain open. Multiple agents can share mistaken assumptions; an AI review is not automatically independent professional review. | Q6, Q7; U4, U5 |
| F07 / Before requirements | A few templates will make one audit model fit every practice. | **The adaptability goal is accepted; the mechanism is unproven.** Financial assertions/materiality, operational controls, advisory work, and IT access testing can differ in objects, methods, roles, and acceptable outputs. Study contrasting cases. Reusable methods need provenance, versions, allowed overrides, and rules for changes after work starts. | Q8, Q12; U2 |
| F08 / Before pilot | Citations, saved conversations, and rerunnable code establish reliable evidence. | **Insufficient.** We need source identity/version, extraction accuracy, completeness of the population, calculations, sampling parameters, exceptions, contrary evidence, and a clear distinction between source facts and conclusions. Hashes do not prove source authenticity or completeness. Deterministic calculations may be repeatable while generated narrative remains variable. | Q9, Q14; U5, U6 |
| F09 / Before pilot | A successful action or a finished chat means the work is accepted or the record is updated. | **Unsupported.** Execution, output validation, human review, formal approval, and external delivery are separate states. A timeout can occur after an external action succeeded; retries can duplicate it. Changes to evidence or methods can invalidate downstream work and approvals. | Q4, Q7; U3–U6 |
| F10 / Before pilot | More persistent memory and cross-engagement context are always helpful. | **Tradeoff requiring explicit scope.** Old conclusions, revoked source access, client confidentiality, superseded methods, and unrelated assignments can contaminate a new task. Reusable organisational knowledge should be distinguished from engagement evidence and personal memory. | Q10; U4, U5 |
| F11 / Before architecture | Local installation implies local/private processing for the future product. | **Incorrect inference.** The folder-only rule governs this research installation. Files, execution, inference, connector traffic, logs, and backups may each have different locations. The future deployment constraint must come from intended users and their actual data policies. | Q1, Q11; U1, U4 |
| F12 / Before pilot | Broad automation will necessarily save time and be economical. | **Unmeasured.** Generation time is only one part of total work. Measure accepted deliverables, reviewer corrections, missed/false exceptions, retries, tool/model costs, data preparation, and operational support. A fast draft that requires extensive reconstruction may be poor value. | Q12, Q14, Q16; U6, U7 |
| F13 / Before positioning | A conversational audit interface alone is a distinctive advantage. | **Needs challenge even for a personal tool.** Diligent already describes agent assistance, and DataSnipper documents prompt-driven Excel testing. Value must be demonstrated in the practitioner's actual work, such as reliable evidence handling, flexible methods, cross-system work, or lower review effort. This is an inference to test, not a competitor ranking. [DataSnipper Excel Agents](https://knowledge.datasnipper.com/en/articles/741967-how-to-efficiently-perform-batch-payment-testing-with-excel-agents). | Q12, Q13; U2, U7, U8 |
